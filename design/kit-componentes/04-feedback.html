Feedback: mensajes, toasts, skeletons y progreso

El sistema habla cuando hay algo que resolver. Mensaje inline para el contexto que queda, toast para lo efímero, skeleton para la espera y barra para el avance. Ningún spinner suelto: la espera se dibuja con la forma de lo que va a llegar.

Mensajes inline

Quedan en la página porque el problema sigue abierto. Cuatro severidades, siempre con ícono, título, una línea de qué pasó y la acción que lo resuelve. El error no se queda sin salida.

bw-message · severity
hoy: p-message · etapa 3 nativo

Toast stack

Tres como máximo, apilados arriba a la derecha, con el ancho fijo de 320 px para que el texto no baile. Se van solos a los 5 s; si el mouse está encima, esperan. La X siempre está.

bw-toast · stack · duration 5000
hoy: p-toast + MessageService

Auto-dismiss 5 s — el timer se pausa con hover y con foco de teclado. Los toasts con acción destructiva o de pago no se descartan solos: esperan un click explícito.

Skeletons

La espera tiene la forma de lo que viene: card, fila de tabla y lista. Shimmer nativo, sin librería, de --bw-surface-muted a --bw-100. Nunca un spinner de página completa.

bw-skeleton · variant card | row | list
hoy: p-skeleton

Con prefers-reduced-motion: reduce el shimmer se apaga y el bloque queda estático en --bw-surface-muted. La forma se mantiene: no hay pulso ni gradiente en movimiento.

Progreso

Determinado cuando el sistema sabe cuánto falta (perfil fiscal, subida de documentos), indeterminado cuando no. La barra es de 8 px y va sobre la superficie, nunca encima de una card de dato.

bw-progress · value · indeterminate
hoy: p-progressBar / p-progressSpinner

Estado vacío

Un vacío no es un error: es una invitación. Título, una línea que explique el contexto y la acción primaria. Si depende de un filtro, se dice en la segunda línea.

bw-empty-state · title · description · action
hoy: markup suelto en agenda

Hacé

  • Skeleton para la carga de lista y de detalle; el spinner vive dentro del botón que disparó la acción.
  • Todo error ofrece una acción: Reintentar, Ver detalle o Registrar pago.
  • Decí qué no se modificó: “No se modificó ningún dato”.
  • Un toast por evento; el stack no pasa de tres.

No hagas

  • Validación de formulario con toast: el error va en el campo, con texto y borde.
  • Auto-dismiss en confirmaciones destructivas: esperan un click explícito.
  • Skeleton para un botón o un label: ahí va spinner o nada.
  • Mensaje de error sin ícono ni severidad: el color solo no alcanza.
