Input

Un campo, una pregunta. El label va siempre arriba y visible; el placeholder es un ejemplo, nunca la etiqueta. El error aparece debajo y reemplaza al helper, con borde e ícono además del texto.

bw-input · value · invalid · hint
hoy: p-inputtext envuelto · iconfield nativo

Select

Con menos de 7 opciones, un select está bien; con más, searchable y filtro dentro del listbox. La opción elegida se marca con check, no solo con fondo. El listbox es un mock estático: en producto lo posiciona PrimeNG.

bw-select · value · options · searchable · invalid
hoy: p-select (overlay + teclado)

Checkbox y radio

Checkbox para varias respuestas, radio para una sola. El estado indeterminado existe y se explica con un helper (“3 de 8”). El radio group lleva fieldset y legend: la pregunta también tiene label.

bw-checkbox · checked · indeterminate · disabled
bw-radio · checked · name · hoy: p-checkbox / p-radiobutton

Toggle

El toggle aplica al instante y por eso necesita un helper que diga qué cambia. Si hay que guardar para que tome efecto, no es toggle: es checkbox dentro del formulario.

bw-toggle · checked = model() · disabled
hoy: p-toggleswitch · el chip confirma el estado persistido

Número y contraseña

La plata se escribe en CLP, sin decimales y con separador de miles. La contraseña se revela con un ojo que anuncia su estado con aria-pressed; el error dice qué pasó, no “campo inválido”.

bw-inputnumber · value · mode currency · locale CLP
bw-password · value · reveal · hoy: p-inputnumber / p-password

Reglas del formulario

Cuatro acuerdos que valen para toda la app, incluso cuando el campo todavía lo dibuja PrimeNG.

bw-form-field · label + control + helper/error
hoy: p-inputtext · p-select · p-toggleswitch

Hacé

  • Label visible siempre; el placeholder es un ejemplo, nunca la etiqueta.
  • Error con texto: qué pasó y cómo se corrige, además del borde.
  • Una sola acción primaria por formulario: el resto es Cancelar o ghost.
  • Todo valor sale de un token --bw-*; el CLP se formatea sin decimales.

No hagas

  • Campos que se identifican solo por el placeholder: desaparece al escribir.
  • Marcar error solo con rojo: sin texto ni ícono no se entiende.
  • Dos botones primarios compitiendo en el mismo footer.
  • Hex, rgba() sueltos ni tamaños mágicos fuera de los tokens.
